## Why this matters

wuphf's core will host the settings store, and its Go connectors must read
their own settings, be told when they change, and show the settings panel to
the owner on Telegram and Discord. That needs the store and the panel engine
reachable over the network, in a form any language can use. A generic
service in botconf (not in wuphf) means any botconf host, the assistant bot
included, gets remote editing by mounting it, and the Go SDK (plan 006)
targets one contract.

## Design decisions (settled with the owner — do not revisit)

| # | Decision |
|---|---|
| 1 | A generic `botconf.v1.Settings` service in `proto/`, plus a `botconf-grpc` crate serving any `SettingsStore` with tonic. Hosts mount it. |
| 2 | RPCs: `Describe`, `List`, `Get`, `Set`, `Unset`, `Add`, `Remove`, `Reload`, `Render`, `Act`, `Watch`. |
| 3 | `Watch` streams changes; connectors use it to receive their own settings. |
| 4 | Authorization is the **host's**: the service passes the caller's claimed actor and the request metadata to a host hook, which returns the principal to record or refuses. botconf decides nothing. |
| 5 | Values travel as JSON strings. |
| 6 | Panels are rendered by the engine (004); remote front ends only draw `Screen`s and send back tokens and answers. |

Decided while planning. Items marked "confirmed" were confirmed by the owner
on 2026-10-25; the others are open to review:

- **tonic 0.12 and prost 0.13, matching wuphf.** wuphf adds services to one
  tonic 0.12 `Server::builder()`. A service generated by a different tonic
  major implements a different version of tonic's service traits and cannot
  be added to that server. So `botconf-grpc` pins the same majors as its
  first host. Upgrading tonic becomes a coordinated change (botconf first,
  then hosts); the crate's docs say so.
- **The server keeps no per-conversation state** (confirmed by the owner
  2026-10-25, with the hybrid tokens of plan 004). The panel's pending
  `Question` goes to the client as an encoded string and comes back with the
  answer (plan 004 made questions encodable). Tokens are the engine's hybrid
  tokens (plan 004, "Tokens"): most are stateless encodings, and long ones
  are handles in the `TokenStore` that the host gave the `Panel`. The
  service never touches that store directly. It is the host's, so a host
  serving panels remotely gives the `Panel` a persistent store (wuphf passes
  its sqlx one). Then any number of clients and server restarts are fine,
  and a handle the store no longer has comes back as a stale press, never as
  a wrong action.
- **Describe sends resolved descriptors.** `Choices::Dynamic` (a Rust
  function) and `KeysOf` are resolved against the current snapshot, so the
  wire only carries concrete choices. Descriptors are owned (`Shared`, plan
  009), so static and dynamic sections serialize the same way. A client
  re-describes after a `Watch` event with `catalog_changed`.
- **Watch scope.** The `subscribe` mechanism below is confirmed by the owner
  (2026-10-25); the prefix scope is open to review. A watch names key prefixes. It first sends the current
  value of every runtime key under them, then an event per change listing
  the keys under the prefixes whose effective value or source changed.
  Registrations and removals of dynamic sections under a prefix set
  `catalog_changed`. To notice changes the store gains
  `SettingsStore::subscribe() -> tokio::sync::watch::Receiver<Arc<Snapshot<S>>>`
  (a `watch::Sender` updated in `publish`).
- **Act is one RPC** (confirmed by the owner 2026-10-25), with a `oneof` (press a token, answer a question, run a
  text command) and returns the engine's `Reaction`. Panel refusals
  (`PanelError::Rejected`) come back inside the response, not as gRPC errors,
  so the client shows them; infrastructure failures are gRPC errors.

### Step 1: The proto

Create `proto/botconf/v1/settings.proto`. Exact names and field numbers may
be refined while writing it, but keep this structure and write a comment on
every service, RPC and field:

```proto
syntax = "proto3";

package botconf.v1;

option go_package = "github.com/propheci/botconf/go/settingspb;settingspb";

// A program's runtime settings: the keys that can change while it runs,
// their values (config file < environment < stored overrides), and a
// settings panel to show to people. Authorization is the host's: every
// request may carry the actor it acts for, and the host decides.
service Settings {
  // The runtime settings with their kinds, choices resolved now.
  rpc Describe(DescribeRequest) returns (DescribeResponse);
  // Every runtime setting's value and source, entry overrides, ignored and
  // parked values.
  rpc List(ListRequest) returns (ListResponse);
  rpc Get(GetRequest) returns (ValueEntry);
  rpc Set(EditRequest) returns (ChangeResponse);
  rpc Unset(UnsetRequest) returns (ChangeResponse);
  rpc Add(EditRequest) returns (ChangeResponse);
  rpc Remove(EditRequest) returns (ChangeResponse);
  rpc Reload(ReloadRequest) returns (ChangeResponse);
  // A page of the settings panel.
  rpc Render(RenderRequest) returns (RenderResponse);
  // Press a button, answer a question, or run a text command.
  rpc Act(ActRequest) returns (ActResponse);
  // The values under some keys now, then every change to them.
  rpc Watch(WatchRequest) returns (stream WatchEvent);
}

// Who a request acts for, as the client claims it: e.g. the Telegram user
// who pressed a button. The host's authorizer decides whether to trust it.
message Actor {
  string domain = 1;   // e.g. "telegram.user"
  string id = 2;
}

// ---- descriptors ----
message DescribeRequest { Actor actor = 1; }
message DescribeResponse {
  repeated SettingDescriptor settings = 1;
  repeated SectionDescriptor sections = 2;
}
message SectionDescriptor { string id = 1; string path = 2; string title = 3; string description = 4; bool dynamic = 5; }
message SettingDescriptor {
  uint32 position = 1;   // stable while the program runs
  string key = 2;
  string title = 3;
  string description = 4;
  bool per_entry = 5;
  Kind kind = 6;
  string section = 7;    // empty for top-level settings
}
message Choice { string value = 1; string label = 2; }
message Kind {
  oneof kind {
    JsonKind json = 1;
    TextKind text = 2;
    NumberKind number = 3;
    OneOfKind one_of = 4;
    SetOfKind set_of = 5;
    RefKind ref = 6;
    FormKind form = 7;
    MapKind map = 8;
  }
}
message JsonKind {}
message TextKind { bool optional = 1; }
message NumberKind { int64 min = 1; int64 max = 2; string unit = 3; repeated int64 suggestions = 4; bool optional = 5; }
message OneOfKind { repeated Choice choices = 1; bool custom = 2; bool optional = 3; }
message SetOfKind { repeated Choice choices = 1; bool inverted = 2; }
message RefKind { string domain = 1; bool many = 2; }
message FormField { string key = 1; string title = 2; Kind kind = 3; string group = 4; }
message FormKind { repeated FormField fields = 1; string initial_json = 2; }
message MapKind { bool limited_names = 1; repeated Choice names = 2; Kind value = 3; }

// ---- values ----
enum Source { SOURCE_UNSPECIFIED = 0; SOURCE_DEFAULT = 1; SOURCE_FILE = 2; SOURCE_ENVIRONMENT = 3; SOURCE_STORED = 4; SOURCE_OTHER = 5; }
message ValueEntry {
  string key = 1;
  optional string value_json = 2;   // unset: no value at all
  Source source = 3;
  string source_name = 4;           // for SOURCE_OTHER, e.g. "connector telegram-1"
  string description = 5;
}
message ListRequest { Actor actor = 1; }
message ListResponse {
  repeated ValueEntry settings = 1;
  repeated ValueEntry entries = 2;
  repeated Ignored ignored = 3;
  repeated ValueEntry parked = 4;
}
message Ignored { string key = 1; string reason = 2; }
message GetRequest { Actor actor = 1; string key = 2; }
// `value` is read like typed input: JSON if it parses, otherwise text.
message EditRequest { Actor actor = 1; string key = 2; string value = 3; }
message UnsetRequest { Actor actor = 1; string key = 2; }
message ReloadRequest { Actor actor = 1; }
message ChangeResponse {
  bool changed = 1;                 // false: nothing was overridden (Unset)
  optional string previous_json = 2;
  ValueEntry current = 3;
  repeated string lints = 4;
}

// ---- panel ----
message Limits { uint32 token_bytes = 1; uint32 text_chars = 2; uint32 max_rows = 3; uint32 max_per_row = 4; }  // max_rows 0: none
enum Style { STYLE_PLAIN = 0; STYLE_BOLD = 1; STYLE_ITALIC = 2; STYLE_CODE = 3; STYLE_CODE_BLOCK = 4; }
message Span { Style style = 1; string text = 2; }
message Text { repeated Span spans = 1; }
message Button { string label = 1; string token = 2; }
message Row { repeated Button buttons = 1; }
message Screen { Text text = 1; repeated Row rows = 2; }
message Picker { string domain = 1; bool many = 2; }
message Ask {
  string question = 1;              // opaque; send it back with the answer
  Text text = 2;
  Picker picker = 3;                // unset: typed answer only
  optional string current = 4;
}
message Page {                       // opaque page reference
  oneof page { HomePage home = 1; string section = 2; string token = 3; }
}
message HomePage {}
message RenderRequest { Actor actor = 1; Page page = 2; Limits limits = 3; }
message RenderResponse { Screen screen = 1; }
message Answer {
  string question = 1;
  oneof input { string text = 2; Picked picked = 3; Cancel cancel = 4; }
}
message Picked { string domain = 1; repeated string ids_json = 2; }
message Cancel {}
message ActRequest {
  Actor actor = 1;
  Limits limits = 2;
  oneof act { string press = 3; Answer answer = 4; string command = 5; }
}
message ActResponse {
  optional Screen screen = 1;       // redraw the panel message
  optional Screen post = 2;         // post a new message
  optional string notice = 3;
  optional Ask ask = 4;
  bool closed = 5;
  optional string rejected = 6;     // the press or answer was refused; show this
  // A stale press (plan 004): `notice` is set and `screen` is the redrawn
  // panel; the client shows the notice and redraws, like any other reaction.
  bool stale = 8;
  optional Text reply = 7;          // a text command's reply
}

// ---- watch ----
message WatchRequest { Actor actor = 1; repeated string prefixes = 2; }
message WatchEvent {
  repeated ValueEntry values = 1;   // first event: every key; then: the changed keys
  bool initial = 2;
  bool catalog_changed = 3;         // re-Describe: sections registered or removed
}
```

Public API:

```rust
/// What a request wants to do, for the authorizer.
pub enum Operation<'a> {
    Describe,
    Read { key: Option<&'a str> },        // List (None) and Get
    Change { key: &'a str },              // Set, Unset, Add, Remove
    Reload,
    Panel,                                // Render and Act
    Watch { prefixes: &'a [String] },
}

/// Who the host lets a request act as; recorded as the author of changes.
pub struct Principal { pub actor: Option<String> }

/// The host's decision on each request.
pub trait Authorizer: Send + Sync + 'static {
    fn authorize(
        &self,
        metadata: &tonic::metadata::MetadataMap,
        actor: Option<&proto::Actor>,
        operation: Operation<'_>,
    ) -> Result<Principal, tonic::Status>;
}

pub struct SettingsService<S: Schema> { /* store, panel, authorizer, on_change */ }

impl<S: Schema> SettingsService<S> {
    pub fn new(panel: Arc<botconf_panel::Panel<S>>, authorizer: impl Authorizer) -> Self;
    /// Called after every change made through the service.
    pub fn on_change(self, hook: impl Fn(Arc<Change<S>>) + Send + Sync + 'static) -> Self;
    pub fn into_server(self) -> proto::settings_server::SettingsServer<Self>;
}

pub mod proto { tonic::include_proto!("botconf.v1"); }
```

There is no default authorizer (confirmed by the owner 2026-10-25): a host must choose (document a
`AllowAll` for tests only, behind `#[cfg(test)]` or a `testing` feature).

Mapping rules (write them as small `From`/conversion functions with tests):

| botconf | wire |
|---|---|
| `CatalogEntry` (live positions only) | `SettingDescriptor` (position, key, title, description, per_entry, kind, section id) |
| `Kind` | `Kind` oneof; `OneOf`/`SetOf` choices and `Map` names resolved with `kind.choices(&snapshot)`; `Form.initial` as `initial_json` |
| `Source::{Default, File, Environment, Stored, Other(name)}` | `Source` enum + `source_name` |
| `Value` | `value_json` (`serde_json::to_string`); absent value: field unset |
| `SettingsError::UnknownKey` | `NOT_FOUND` |
| `InvalidValue`, `NotAList`, `NotAnEntry` | `INVALID_ARGUMENT` with the error's text |
| `InvalidBase` | `FAILED_PRECONDITION` |
| `Storage` | `INTERNAL` ("the settings storage failed"), logged with `tracing::error!` |
| `Outcome::NotOverridden` | `ChangeResponse { changed: false }` |
| `Reaction` | `ActResponse` field by field; `PanelError::Rejected(r)` → `rejected = r`; `PanelError::Stale { notice, screen }` → `stale = true`, `notice`, `screen`; `PanelError::Storage` and `PanelError::Tokens` → `INTERNAL` |
| `Input::Picked { ids }` | `Picked.ids_json` parsed with `serde_json::from_str` (bad JSON → `INVALID_ARGUMENT`) |

Each RPC: call `authorizer.authorize(…)` first (a refusal returns its
`Status` unchanged and touches nothing), then the store or panel with
`by = principal.actor`, then `on_change` for `Changed`/`Reloaded` outcomes and
reactions with a `change`.

`Watch`: authorize with the prefixes; take `store.subscribe()`; send the
initial event (every live catalog key at or below a prefix, plus dynamic
sections' keys); then for each new snapshot compare `value` and `source` of
those keys with the previous snapshot and send the changed ones (skip empty
events); set `catalog_changed` when the catalog `Arc` changed and any added
or removed key is under a prefix. End the stream when the client goes away.

### Step 4: Tests

`rust/botconf-grpc/src/tests.rs`, in-process server on `127.0.0.1:0` (the
wuphf harness pattern), a small toy schema (a greeting text, a number with
bounds, a `SetOf`, a `Ref` list, one form) with `MemoryStorage`, and a
recording authorizer:

1. `describe_resolves_choices` — dynamic choices arrive as concrete
   `Choice`s; positions match `store.catalog()`.
2. `set_validates_like_the_store` — out-of-range number → `INVALID_ARGUMENT`
   with the reason; nothing stored.
3. `set_records_the_principal` — the authorizer maps the claimed actor to
   `"tg:42"`; the stored override's `by` is `"tg:42"`.
4. `refused_requests_change_nothing` — authorizer returns
   `PERMISSION_DENIED` for `Change`; `Set` fails with it; store unchanged.
5. `unknown_keys_are_not_found`.
6. `unset_without_override_reports_unchanged`.
7. `render_and_press_toggle_a_choice` — render home, press the `SetOf`
   setting's token, press a toggle token: the value changed and the response
   carries the redrawn screen.
8. `ask_and_answer_round_trip` — press "Change" on the text setting →
   `ask.question`; `Act(answer { question, text })` sets it.
9. `rejected_presses_come_back_in_the_response` — a garbage token →
   `rejected` set, no gRPC error.
10. `text_commands_reply` — `Act(command: "get greeting")` → `reply`.
11. `watch_sends_initial_values_then_changes` — prefix `greeting`: initial
    event with one value; `Set` elsewhere (other key) sends nothing; `Set`
    greeting sends one event (use the receiver, no sleeps).
12. `watch_reports_dynamic_sections` — register a dynamic section under a
    watched prefix: `catalog_changed` and its values arrive.
13. `storage_failures_are_internal` — a `Storage` that fails on write →
    `INTERNAL`.
14. `stale_handles_come_back_as_stale` — give the `Panel` a
    `MemoryTokenStore`, render a screen whose button needs a handle (a map
    entry with a long name), build a second `Panel` and service over the
    same settings store with an empty token store (a restart without a
    persistent store), press the handle → `stale = true`, `notice` set,
    `screen` is the home screen, no gRPC error.
15. `handles_survive_a_new_service_with_the_same_store` — the same, but both
    services share one `MemoryTokenStore`: the press works.
